## 2. 做法

### 2.1 脚本全量

`scripts/audit_tasks.py`（规则在 `taskgen_v2/audit.py`）在 3,450 道题上跑一遍，也在 DySQL 的 1,062 道 gold 上跑一遍作对照：DySQL 自己也常见的现象算风格，不算毛病。每条规则只负责标出"要读的题"，是不是坏题由人来判。

规则共 13 条：
- 指认的行不唯一（instr_matches_more）
- gold 的条件比题目点名的键宽（where_broader）
- 写入的外键指向不存在的行（dangling_fk）
- 题目说的现值和库里不符（claim_not_found）
- 写入的值和这一列的惯例不同（case_mismatch、new_category、format_shape、type_mismatch、padded_value）
- 一次复制多行时，题里列出的顺序和表里的顺序不同（copy_order）
- 写入的键和已有的行冲突（key_collision）
- 新插入的名称库里已经有（duplicate_name）
- 一条 UPDATE 什么也没改（noop_update）
- 先改一行，后面又删掉它（update_then_delete）
- 说话人的身份缺失、有歧义，或题里出现了别人的名字（identity_*）
- 题目和 DySQL 的题近似重复（dysql_near_dup）

其中 key_collision、duplicate_name、noop_update、update_then_delete 四条，是抽读发现问题后补上的（7c5ae03）。复制顺序这条也是读后改的：只算被复制的行内容不同的情况，因为 WWE 有些比赛存了好几份一模一样的行。

几条规则的说明：
- **复制顺序。** gold 用一条 INSERT … SELECT 复制，新行按表里的顺序编号。agent 如果按题里列出的顺序一行行复制，新行的 id 会对调，按全库哈希判分就失败。
  - 32 道里，beer_factory 8 道，shipping 7 道，WWE 5 道。
  - 除了删，也可以改题：把题里的行号按表里的顺序重新排列，终态就唯一了。
- **键冲突。** 4 道都是 Airlines 的修复题，新票号已经属于别的订单。Airlines 的表没有声明主键和唯一约束，所以检查拦不住。
- **重复名称。** 题目说"缺少 X，请加上"，库里其实有 X（例如 olympics 的 '1964 Summer'、IPL 的 'Gujarat Lions'、books 的 'Portuguese'）。
  - 会核对的 agent 会指出 X 已存在，不去插入，终态就和 gold 不一样。
  - 拿这类题训练，还会教 agent 不查就往查找表里插重复值。
- **悬空外键。** 删的 6 道指向不存在的人或电影：college_2 的教师和学生、movie 742、school_scheduling 一个默认为 0 的院系。
  - 其余 15 道是 synthea 指向描述查找表、hr_1 的国家 'Ox'（库里已有地点用它）这类，不影响判分。
- **其他事实：**
  - gold 里带 WHERE 的 6,303 条语句，条件里的值都来自题目或说话人的记录（检查规则保证）。DySQL 是 2,028/2,070。
  - 人物题的身份标记为 0：每道题都给了键或名字，同名歧义 0 道。
