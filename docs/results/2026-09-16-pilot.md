## What the five trajectories show (qualitative, for later reward design)

1. **Fabricated `<result>` is the dominant failure mode, 4 of 5 tasks.** The agent writes a SQL block, then *writes its own `<result>…</result>`*, then continues (often with more SQL blocks) in the same message. The env executes only the first block per turn; everything after it is never run. Task 1 lost exactly this way: first block was a SELECT, the two UPDATEs behind the fake results never executed. This matches the paper's Figure 7 observation and violates the policy rule "at most one sql call at a time". It is the first thing an RL reward should penalize (e.g. any `<result>` in assistant text, or >1 SQL block per turn → 0).
2. **Semantic drift on writes**: task 0 did `UPDATE payment SET amount=0` where gold is `DELETE FROM payment`; task 2 did `active='N'` where gold is `active='0'`. Both are plausible readings the hash judges as wrong. Expect this class to be a noise floor that no reward fixes without schema/value lookups.
3. **Scope refusal**: task 2 declared "refund processing is outside the scope" and skipped two of three gold writes.
4. `last_update = CURRENT_TIMESTAMP` written by the agent was correctly ignored by the volatile-column filter.
5. `confirmed_before_write` = 100 % is the loose keyword rule firing; it will need tightening before it is used as a reward term.
6. User sim behaved: revealed info incrementally, confirmed before writes, emitted `###STOP###` cleanly in all 5 runs. No premature stops observed.

## Decisions for the user

1. **Concurrency for the full run.** Recommend a 10-minute probe: restart agent with `--max-num-seqs 32`, user sim `--max-num-seqs 16`, rerun the same 5 tasks ×2 trials at concurrency 10 and check aggregate tok/s and preemptions. Then run full at the concurrency that probe supports.
2. **Go straight to full run (13 envs, pass@1) after the probe**, or first do a second-round pilot (3 envs × 8 tasks, or thinking-off comparison)?
3. Keep 72B as user sim? It is 11 % of compute; no reason to change it for throughput.
