# Single-turn reasoning-RL for text-to-SQL (2025-01 to 2026-10): how the cold-start / SFT stage is handled

Scope: single-turn text-to-SQL papers that train with RL (GRPO/PPO/DAPO/DPO) or that are the SFT data sources these papers rely on. Multi-turn/agentic systems (SkyRL-SQL, MTIR-SQL, SQL-Trail, TRUST-SQL, Progress-SQL, MARS-SQL) are only mentioned where they bear directly on the SFT-vs-RL question; they are covered by another researcher. All numbers are execution accuracy (EX, %) on BIRD dev unless noted. "Month" = first arXiv version unless noted; all details below were read from the arXiv HTML/abstract pages via fetch; where the fetch did not surface a value it is marked "not stated".

## Per-paper fact sheet (base model, SFT?, SFT data, RL algo, reward, data size, ablation)

### Takeaway
Of 20+ single-turn RL papers, roughly half apply GRPO directly to an instruction-tuned coder model with no SFT (Reasoning-SQL, CSC-SQL, CogniSQL-R1-Zero, DeepRetrieval, RingSQL, SQL-Zero, ReEx-SQL as far as stated), and the other half either distil reasoning traces from a stronger model first (Think2SQL, Reward-SQL, FINER-SQL, SLM-SQL, AGRO-SQL, Graph-Reward-SQL, Sparks) or start RL from an already-SFT'd public checkpoint (Arctic-Text2SQL-R1 and SQL-R1's best 7B config both start from OmniSQL). Execution-match remains the dominant reward; most add a small format term.

### Cited Findings

**Reasoning-SQL (Pourreza et al., Google; Mar 2025, arXiv 2503.23157)**
- Base: Qwen2.5-Coder 3B / 7B / 14B (instruct). GRPO applied directly to the instruct model; no SFT before RL is described. SFT appears only as a *baseline*: "Direct SFT" on gold BIRD SQL and "STaR-SFT" with CoT traces generated by Gemini-1.5-Pro-002 using the CHASE-SQL divide-and-conquer prompt — [arXiv HTML](https://arxiv.org/html/2503.23157v2)
- RL data: BIRD train filtered from 9,428 to 8,026 examples by dropping queries flagged incorrect by both Gemini-2.0-flash and GPT-4o. GRPO: lr 1e-6, effective batch 32, 3 epochs, group size 6, 8xH100 — [arXiv HTML](https://arxiv.org/html/2503.23157)
- Reward = weighted sum: execution accuracy (weight 3), LLM-as-judge/AI feedback (2), syntax check, schema linking (Jaccard), n-gram similarity, format (1 each); weights "carefully chosen to ensure that no incorrect SQL query can achieve a higher overall reward than a correct query" — [arXiv HTML](https://arxiv.org/html/2503.23157)
- BIRD dev, Base / SFT / GRPO(all rewards): 3B 45.17 / 55.9 / 58.67; 7B 58.73 / 61.53 / 64.01; 14B 63.1 / 63.75 / 65.31 — [arXiv HTML v2](https://arxiv.org/html/2503.23157v2)
- Generalisation to Spider / Spider-DK / Spider-Syn: 7B SFT 68.08 / 62.8 / 51.93 vs 7B GRPO 78.72 / 73.27 / 69.34; 14B SFT 75.04 / 69.15 / 61.02 vs 14B GRPO 81.43 / 73.03 / 72.63 — [arXiv HTML v2](https://arxiv.org/html/2503.23157v2)
- Reward ablation (7B, BIRD dev, as reported by the fetch): execution only 68.90 -> +syntax 68.97 -> +schema 69.23 -> +n-gram 69.94 -> all 70.66 (these numbers are higher than the 64.01 headline; the fetch did not state the decoding setting, so treat the row as "relative ordering" evidence). Training without a reasoning step cost ~2 points — [arXiv HTML v2](https://arxiv.org/html/2503.23157v2)
- Abstract claim: "RL-only training with our proposed rewards consistently achieves higher accuracy and superior generalization compared to supervised fine-tuning (SFT)"; 14B beats o3-mini by 4% and Gemini-1.5-Pro-002 by 3% on BIRD — [arXiv abs](https://arxiv.org/abs/2503.23157)

**SQL-R1 (Ma et al.; Apr 2025, NeurIPS 2025; arXiv 2504.08600)**
- Base: Qwen2.5-Coder 3B / 7B / 14B. RL algo GRPO with KL, 8 candidates per query. Reward: format +-1; execution +2 / 0 / -2; result +3 / 0 / -3; length term proportional to response/SQL length — [arXiv HTML](https://arxiv.org/html/2504.08600)
- RL data: SynSQL-Complex-5K (5,000 complex NL-SQL pairs sampled from SynSQL-2.5M, CoT dropped). SFT cold-start data (when used): SynSQL-200K, 200,000 samples stratified 50K per difficulty level, with think/answer tags — [arXiv HTML](https://arxiv.org/html/2504.08600)
- Main results (Spider dev / Spider test / BIRD dev): 3B 78.1 / 78.9 / 54.6; 7B 87.6 / 88.7 / 66.6; 14B 86.7 / 88.1 / 67.1 — [arXiv HTML v5](https://arxiv.org/html/2504.08600v5)
- Cold-start ablation (Table 4), 7B: RL only (no SFT) Spider-test 86.1 / BIRD 63.1; SFT on SynSQL-200K then RL 86.4 / **59.2** (worse than RL-only); SFT on SynSQL-2.5M (i.e. start from OmniSQL-7B) then RL 88.7 / 66.6 (best). 14B: RL only 88.1 / 67.1; OmniSQL-14B then RL 87.6 / 66.6 — [arXiv HTML v5](https://arxiv.org/html/2504.08600v5)
- Authors' conclusion: "SFT cold-start training is not universally essential for RL-based NL2SQL models. Its effectiveness is contingent upon the origin and volume of the training data." — [arXiv HTML v5](https://arxiv.org/html/2504.08600v5)

**Arctic-Text2SQL-R1 (Snowflake; May 2025, v2 Jan 2026; arXiv 2505.20315)**
- Base: Qwen2.5-Coder 7B / 14B / 32B. 7B and 14B RL started from the **OmniSQL** (SFT) checkpoints; 32B tried both Qwen2.5-Coder-32B-Inst and OmniSQL-32B. The authors did **not** run their own SFT; they relied on OmniSQL's public SFT checkpoints — [arXiv HTML v2](https://arxiv.org/html/2505.20315v2)
- Reward: "1, if the execution results exactly align with ground truth; 0.1, if syntax is correct and SQL is executable; 0, otherwise." — [arXiv HTML](https://arxiv.org/html/2505.20315)
- Reward hacking: "More fine-grained reward designs induced 'lazy' behaviors, where models pursued local optima for short-term rewards rather than global correctness." Partial rewards they tried and rejected: execution, syntax, n-gram overlap, schema conformance, format matching — [arXiv HTML v2](https://arxiv.org/html/2505.20315v2)
- RL data: BIRD train 8,017 (filtered) + Spider train/dev 7,957 (filtered) + Gretel-Synth-Filtered 11,811 = ~27,785; about 3,100 samples with empty execution results were removed because "such examples can disrupt the learning process by producing spurious or uninformative rewards"; adding unfiltered synthetic data degraded results — [arXiv HTML v2](https://arxiv.org/html/2505.20315v2); [arXiv HTML](https://arxiv.org/html/2505.20315)
- GRPO settings: 16 rollouts, batch 256, update batch 128, temperature 0.8, KL beta 0.001, clip 0.2, online RL — [arXiv HTML v2](https://arxiv.org/html/2505.20315v2)
- Init ablation (32B, Table 5): Qwen2.5-Coder-32B-Inst + batch RL 64.9 vs OmniSQL-32B + online RL 67.9; final OmniSQL-32B 70.5. Stated: "Stronger SFT models (e.g., OmniSQL) consistently yield better downstream RL results." Note the comparison conflates init with online-vs-batch RL — [arXiv HTML v2](https://arxiv.org/html/2505.20315v2)
- Final: 7B 68.9 dev / 88.8 test(?); 14B 70.1 / 89.4; 32B 70.5 / 88.7 (the "test" column as returned by the fetch looks like Spider-test, not BIRD-test; verify before quoting) — [arXiv HTML v2](https://arxiv.org/html/2505.20315v2)

**Think2SQL (Papicchio et al.; Apr 2025, TMLR; arXiv 2504.15077)**
- Base: Qwen2.5-Coder-Instruct 0.5B / 1.5B / 3B / 7B / 14B, trained with Open-R1 — [arXiv HTML](https://arxiv.org/html/2504.15077)
- SFT data: DeepSeek-R1 reasoning traces (temp 0.7, top-p 0.95) on BIRD train; after filtering 421 bad/duplicate rows, kept only traces with perfect execution: 1,142 examples (193 challenging, 265 medium, 684 simple; 913 train / 229 val). SFT 5 epochs, batch 128, lr 4e-5, 4xA100 — [arXiv HTML](https://arxiv.org/html/2504.15077); [arXiv HTML v5](https://arxiv.org/html/2504.15077v5)
- RL: GRPO, 1 epoch over 9,007 BIRD samples, 8xH100, 40-60 h. Reward R = 0.85*R_text2sql + 0.10*R_format + 0.05*R_tagcount, where R_text2sql is either binary EX or QATCH = mean(cell precision, cell recall, tuple cardinality) — [arXiv HTML](https://arxiv.org/html/2504.15077); [arXiv HTML v5](https://arxiv.org/html/2504.15077v5)
- BIRD dev (fractions): 3B Base 0.382 / SFT 0.460 / RL-QATCH 0.500 / SFT+RL 0.482; 7B Base 0.476 / SFT 0.494 / RL-QATCH 0.561 / SFT+RL 0.537; 14B Base 0.541 / RL-QATCH 0.602. Think2SQL-0.5B 0.254, Think2SQL-1.5B 0.442 (vs base 0.089 and 0.275) — [arXiv HTML](https://arxiv.org/html/2504.15077); [arXiv HTML v5](https://arxiv.org/html/2504.15077v5)
- 7B cross-dataset: Spider 0.826 (SFT+RL), Spider-Syn 0.794 (SFT+RL), Spider-DK 0.731 (RL only), KaggleDBQA 0.441 (SFT+RL) — [arXiv HTML](https://arxiv.org/html/2504.15077)
- Stated findings: "small LLMs benefit most from reasoning-aware SFT and RL"; partial-credit QATCH reward "crucial for guiding models even when outputs are not fully correct"; "Generic reasoning skills are insufficient; models must be explicitly exposed to structured reasoning within the domain." — [arXiv abs](https://arxiv.org/abs/2504.15077); [arXiv HTML](https://arxiv.org/html/2504.15077)

**Graph-Reward-SQL (May 2025, v3 Oct 2025; arXiv 2505.12380)**
- Base: DeepSeek-Coder-1.3B-Ins and 6.7B-Ins for the main experiments; Qwen2.5-Coder-7B/14B-Ins for final benchmarks. SFT warm-up before RL: 2 epochs on a sample of the 200k-Text2SQL dataset equal in size to the Spider train split (8,659); for stepwise experiments BIRD train (9,428) converted to CTE format with GPT-4o — [arXiv HTML](https://arxiv.org/html/2505.12380)
- RL: GRPO (group 16), PPO also tested. Rewards: GMNScore (3.99M-param graph-matching network trained on 20k+ augmented Spider SQL pairs; 0.023 s/sample vs 1.088 s for execution) and StepRTM (rule-based relational-operator-tree match on CTE steps) — [arXiv HTML](https://arxiv.org/html/2505.12380)
- 1.3B results (test-suite acc): Spider EX-reward 65.28 / GMNScore 67.70 / StepRTM+GMNScore 68.67; BIRD 17.21 / 16.10 / 21.97. Qwen2.5-Coder-7B GRPO with EX reward: Spider 78.72, BIRD 64.01. CTE-SFT + StepRTM: +5.87 on BIRD, +0.97 on Spider over outcome-only. Reward hacking not discussed — [arXiv HTML](https://arxiv.org/html/2505.12380)

**CSC-SQL (Sheng & Xu; May 2025; arXiv 2505.13271)**
- Base: Qwen2.5-Coder-3B/7B/14B/32B-Instruct and XiYanSQL-QwenCoder-3B/7B/32B (the latter already SQL-SFT'd); no additional SFT before GRPO is described for the Qwen models ("post-training" with GRPO only). GRPO: 1 epoch on BIRD train, 6 completions, batch 12, lr 3e-6. Reward R = R_EX + 0.1*R_format — [arXiv HTML](https://arxiv.org/html/2505.13271); [arXiv HTML v2](https://arxiv.org/html/2505.13271v2)
- BIRD dev, n=64 samples: Qwen-3B Base+SC 56.15, Base+CSC 60.39, GRPO+SC 60.60, GRPO+CSC 63.34; Qwen-7B Base+SC 64.45, Base+CSC 68.70, GRPO+SC 66.15, GRPO+CSC 69.19; XiYan-32B GRPO+SC 68.95, GRPO+CSC 71.33. BIRD private test: 7B 71.72, 32B 73.67 — [arXiv HTML v2](https://arxiv.org/html/2505.13271v2); [arXiv abs](https://arxiv.org/abs/2505.13271)

**CogniSQL-R1-Zero (Jul 2025; arXiv 2507.06013)**
- Base Qwen2.5-Coder-7B-Instruct; "we apply Group Relative Policy Optimization (GRPO) directly on Qwen2.5-Coder-7B without any supervised warm-up". GRPO G=6, T=0.9, KL beta 0.001; BIRD train 9,428 (prompts >3,000 tokens filtered); 4xA100-40GB, ~34K RL steps — [arXiv HTML](https://arxiv.org/html/2507.06013)
- Reward: format 1/0, soft-format 0.5, correctness 2/0 (execution match), length -0.5 over limit; "alpha_c >> {alpha_f, alpha_sf, alpha_l}" — [arXiv HTML](https://arxiv.org/html/2507.06013)
- Why no SFT (their preliminary experiments): SFT on distilled QwQ-32B traces "dropped from ~52.0% to ~46.0% after SFT"; SFT on self-generated (Qwen-7B, execution-validated) data recovered to ~57.3%; "only by directly optimizing execution-based rewards (via GRPO) did the model reliably improve beyond ~59%". A brief-SFT cold-start variant was compared and pure RL "ultimately achieved marginally higher peak accuracy" — [arXiv HTML](https://arxiv.org/html/2507.06013)
- BIRD dev: 59.97 single sample, 69.68 best-of-6. Released: 36,356 self-generated verified traces and ~5,024 QwQ-32B traces (HF CogniSQL/Reasoning_Traces, CogniSQL/Positive_Sample_Corpus) — [arXiv HTML](https://arxiv.org/html/2507.06013)

**ReEx-SQL (May 2025; arXiv 2505.12768)**
- Base Qwen2.5-Coder-7B-Instruct; GRPO in OpenRLHF, batch 64, lr 2e-6, 8 rollouts at T=1.0, up to N=10 execution interactions inside the reasoning chain (execution-aware reasoning; borderline single-turn). No SFT cold-start stage is described in the paper; RL data split/size not stated — [arXiv HTML v2](https://arxiv.org/html/2505.12768v2)
- Reward weights (format, exact-match, exec, entity, exploration) = (2.0, 1.0, 3.0, 1.0, 2.0). Results: BIRD dev 64.9, Spider dev 88.8, Spider-Realistic 85.2; standard-reasoning GRPO baseline 60.8 vs ReEx 63.4 in the ablation; 51.9% inference-cost reduction on BIRD dev — [arXiv HTML](https://arxiv.org/html/2505.12768); [arXiv abs](https://arxiv.org/abs/2505.12768)

**SQL-o1 (Feb 2025; arXiv 2502.11741)** — SFT only + MCTS; no policy-gradient RL
- Base Llama3-8B (primary), Qwen2.5-7B/14B, CodeLlama-7B, DeepSeek-Coder-7B. SFT with LoRA (lr 1e-5, 2 epochs, batch 32) on a Schema-Aware dataset plus Progressive SQL Generation data (prefix-truncated failure cases), 21,254 pairs over Spider+BIRD. Self-reward R = beta + alpha*log pi(y|x) (beta=100, alpha=0.6) plus execution reward {-1,0,+1} used in MCTS. BIRD dev 63.4 (Llama3-8B), 66.7 (Qwen2.5-7B), 73.1 (Qwen2.5-14B); Spider dev 87.4 — [arXiv HTML](https://arxiv.org/html/2502.11741)

**Alpha-SQL (Feb 2025, ICML 2025; arXiv 2502.17248)** — zero training
- "a 32B open-source LLM without fine-tuning", MCTS with LLM-as-Action-Model and a self-supervised reward; BIRD dev 69.7; +2.5 over best GPT-4o zero-shot — [arXiv abs](https://arxiv.org/abs/2502.17248)

**OmniSQL / SynSQL-2.5M (Mar 2025; arXiv 2503.02240)** — the SFT data source used by SQL-R1, Arctic, SLM-SQL, SkyRL-SQL
- SynSQL-2.5M: 2.5M samples over >16,000 synthetic DBs; generated with Meta-Llama-3.1-8B/70B-Instruct, DeepSeek-Coder-6.7B/33B-Instruct, DeepSeek-Coder-V2-Lite-Instruct, Qwen2.5-7B/14B/32B/72B-Instruct and Qwen2.5-Coder, "larger models assigned a greater share"; filtering = execution validation (syntax errors/timeouts), one query per SQL template, majority vote over CoT candidates — [arXiv HTML](https://arxiv.org/html/2503.02240); [arXiv abs](https://arxiv.org/abs/2503.02240)
- OmniSQL-7B/14B/32B = Qwen2.5-Coder-Instruct SFT'd 2 epochs on SynSQL-2.5M + Spider + BIRD train (LoRA only for 32B). BIRD dev 63.9 / 64.2 / 64.5; Spider dev 81.2 / 81.4 / 80.9; Spider test 87.9 / 88.3 / 87.6 — [arXiv HTML](https://arxiv.org/html/2503.02240)

**Reward-SQL (May 2025 v1; v3 Jun 2026 = SIGMOD/PACMMOD vol. 43; arXiv 2505.04671)** — two versions with different base models
- v1 (May 2025): base Qwen2.5-Coder-7B-Instruct. Cold-start SFT on Chain-of-CTEs (CoCTE) data: 36,103 CoCTEs generated from BIRD train by DeepSeek-R1-Distill-Qwen-32B (multi-sampling) plus o1-mini for diversity, deduplicated by syntax tree to 18,015. PRM trained on 47,287 step-labelled CoCTEs (from 181,665 MCTS rollouts). GRPO with PRM + execution reward. BIRD dev: SFT greedy 54.4; SFT+GRPO greedy 59.7; SFT+GRPO+PRM@32 68.9. SFT needed "due to the lack of existing CoCTE-formatted data" — [arXiv HTML v1](https://arxiv.org/html/2505.04671v1)
- v3 (Jun 2026): base Qwen3-8B; CoCTE data generated by DeepSeek-V3.1 from 5 manual seeds: 51,996 trajectories from 17,462 SQL (90.7% acceptance), AST-filtered; PRM base Qwen2.5-7B-Coder-Instruct, MCTS 8 rollouts. BIRD dev greedy / PRM@8 / PRM@32: SFT only 63.2 / 67.4 / -; GRPO(outcome only) 62.6 / 67.0 / -; GRPO(process+outcome) 66.0 / 68.7 / 70.3 — [arXiv HTML](https://arxiv.org/html/2505.04671)

**DeepRetrieval (Mar 2025, v3 Apr 2025; arXiv 2503.00223)** — PPO; the cleanest SFT vs RL vs SFT->RL grid for 3B
- Base Qwen2.5-3B-Instruct, Qwen2.5-Coder-3B-Instruct, Qwen2.5-Coder-7B-Instruct; PPO+GAE; reward = execution accuracy; trained on BIRD train + Spider train — [arXiv HTML v3](https://arxiv.org/html/2503.00223v3)
- Table 3 (BIRD / Spider dev): Qwen2.5-3B zero-shot 29.66 / 52.90; SFT 33.77 / 56.67; RL from scratch 41.40 / 68.79; SFT + cold-start RL 44.00 / 70.33. Qwen2.5-Coder-3B: 30.77 / 50.97; SFT 39.77 / 58.61; RL 49.02 / 74.85; SFT->RL 50.52 / 74.34. Qwen2.5-Coder-7B: zero-shot 45.24 / 64.89; SFT 44.07 / 65.96; RL 56.00 / 76.01. GPT-4o 55.35 / 73.50 — [arXiv HTML v3](https://arxiv.org/html/2503.00223v3)
- Stated: "RL from scratch achieves better performance than SFT" and "SFT can provide a strong initialization for RL especially when the LLM lacks a certain capability" — [arXiv HTML](https://arxiv.org/html/2503.00223); [arXiv HTML v3](https://arxiv.org/html/2503.00223v3)

**SLM-SQL (Jul 2025, IJCNLP-AACL 2025 Findings; arXiv 2507.22478)** — SFT (distilled data) then GRPO on 0.5B-1.5B
- Base: Qwen2.5-Coder-0.5B-Instruct, Qwen3-0.6B, Llama-3.2-1B-Instruct, DeepSeek-Coder-1.3B-Instruct, Qwen2.5-Coder-1.5B-Instruct. SFT on SynSQL-Think-916K (SynSQL-2.5M CoT re-filtered: drop no-SELECT, duplicate SQL, comment markers; wrap reasoning in tags). GRPO on BIRD train 9,428 with R = R_EX + 0.1*R_format. Merge-revision data SynSQL-Merge-Think-310K from 8 Qwen2.5-Coder-7B-Instruct candidates with execution-group voting — [arXiv HTML](https://arxiv.org/html/2507.22478)
- BIRD dev Base / SFT / SFT+RL / +CSC: 0.5B 42.13 / 65.31 / 70.60 / 72.08; 1.5B 63.54 / 74.53 / 75.15 / 76.72. Removing SFT: -21.93 (0.5B), -8.89 (1.5B) — [arXiv HTML](https://arxiv.org/html/2507.22478). (Note: these BIRD figures are far above other 1.5B results such as FINER-SQL 63.17; the 1.5B 67.08 cited elsewhere — [ACL Anthology](https://aclanthology.org/2025.findings-ijcnlp.92.pdf) — suggests the fetched table may be a different split/setting; verify in the PDF before quoting.)

**FINER-SQL (May 2026; arXiv 2605.03465)** — distilled SFT then GRPO with dense rewards on 0.5B-3B
- Base Qwen2.5-Coder 0.5B / 1.5B / 3B. SFT: "Reasoning Bank" of 37.6K traces = 4 teachers (DeepSeek-R1, GPT-oss-120B, Qwen2.5-72B-Instruct, GPT-4o) x BIRD train, ~$30 via GRAST-SQL schema linking; 2 epochs, lr 2e-5. GRPO: 32 rollouts, lr 8e-6, batch 32, <2 days on 2xA6000 for 3B — [arXiv HTML](https://arxiv.org/html/2605.03465v1)
- Reward R = R_format + R_exec(0 fail / 1 valid / 2 correct) + R_atomic (operation-level Jaccard, [0,1]) + R_memory (alignment to verified traces, [0,1]) — [arXiv HTML](https://arxiv.org/html/2605.03465v1)
- BIRD dev 0.5B 50.85, 1.5B 63.17, 3B 67.73; Spider dev 70.2 / 80.0 / 85.0. 3B: SFT-only start ~63.4 -> 67.73 after GRPO; -2.22 without memory reward (syntax errors 6.0% -> ~10%), -3.26 without atomic, -4.44 without both — [arXiv HTML](https://arxiv.org/html/2605.03465v1)

**RingSQL (Jan 2026, v2 Aug 2026; arXiv 2601.05451)** — RLVR, no SFT, 3B-8B
- Base Qwen2.5-Coder-3B/7B-Instruct, Llama-3.2-3B-Instruct, Llama-3.1-8B-Instruct. No SFT step; RLVR with the SQL-R1 (Ma et al. 2025) progressive reward (format, syntax, correctness, brevity); 4xA100, 1000 steps, batch 4; 8 samples at T=0.8 + self-consistency — [arXiv HTML](https://arxiv.org/html/2601.05451)
- RingSQL-Gen = 5,000 template-generated + GPT-4o-mini-paraphrased pairs (4,000 train / 1,000 dev) over 160 Spider DBs. Qwen-3B BIRD dev: 53.13 (RingSQL-Gen) vs 46.74 (Spider train) vs 46.74 (BIRD train); Spider test 82.53 / 79.74 / 80.48; 6-benchmark avg 69.80 / 68.45 / 68.51. Llama-3.2-3B gained most (+4.74 avg) — [arXiv HTML](https://arxiv.org/html/2601.05451)

**SQL-Zero (Sep 2026; arXiv 2609.04697)** — self-play RL, no SFT, no labels
- Base Qwen2.5-Coder-3B/7B-Instruct as challenger and solver; GRPO; solver reward 1.0 correct / 0.1 valid-but-wrong / 0.0 invalid; challenger reward targets 1-of-5 solve rate + format + template-level repetition penalty (lambda 0.5) to prevent structural collapse; 64 unlabeled BIRD train DBs; 20,000 deduplicated pairs per iteration — [arXiv HTML](https://arxiv.org/html/2609.04697)
- Greedy@1: 3B BIRD dev 45.3 (vs 38.7 zero-shot), Spider test 74.7 (vs 68.0); 7B BIRD 58.4 (vs 51.1), Spider test 82.4 (vs 82.2) — [arXiv HTML](https://arxiv.org/html/2609.04697)

**ExCoT (Snowflake; Mar 2025; arXiv 2503.19988)** — SFT + DPO (not GRPO)
- Base LLaMA-3.1-70B and Qwen2.5-Coder-32B. SFT on GPT-4o few-shot CoT (up to 32 candidates per query, execution-filtered: 5.6k BIRD + 6.1k Spider). Then 1 round off-policy DPO (GPT-4o pairs) + 2 rounds on-policy DPO with execution feedback. BIRD dev / Spider test: LLaMA-70B base 57.37 / 78.81 -> SFT 58.14 / 81.42 -> +off-policy DPO 66.30 / 82.49 -> +on-policy DPO 68.51 / 86.59; Qwen-32B 58.93 / 79.32 -> 59.65 / 81.23 -> 66.23 / 83.98 -> 68.25 / 85.14. "Online-DPO, PPO, and GRPO, are left for future exploration" — [arXiv HTML](https://arxiv.org/html/2503.19988)

**STaR-SQL (Feb 2025; arXiv 2502.13550)** — self-taught (STaR) rationales, same model
- Base Llama-3.1-8B-Instruct; few-shot (P=3) self-generated rationales, gold-SQL-hinted "rationalization" for failures, execution-match filtering, iterate until plateau; 7,000 Spider train problems x 8 solutions; difficulty-based resampling; an ORM verifier trained on all labelled rationales. Spider dev: SFT-only baseline 68.6 EX; STaR-SQL 75.0 EX; with ORM@16 86.6 EX. No BIRD results — [arXiv HTML](https://arxiv.org/html/2502.13550)

**Sparks of Tabular Reasoning via Text2SQL RL (Apr/May 2025; arXiv 2505.00016)**
- Qwen-7B-Instruct and 4-bit DeepSeek-LLaMA-8B; SFT on ~3,500 synthetic CoT (Clinton dataset) then GRPO on BIRD; four partial rewards (execution, string match, clause-level F1, LLM-judge ordinal grades). BIRD dev 15.5 (Qwen) / 8 (LLaMA) — very low absolute accuracy; CRT-QA +7.1 / +14.0 — [arXiv HTML](https://arxiv.org/html/2505.00016)

**Reinforcing Code Generation (Jun 2025; arXiv 2506.06093)** — reward hacking example
- SQLCoder-7B and CodeGemma-7B, GRPO directly on the pre-trained code models (no SFT described), TEMPTABQA-C (2,961 train). Reward: syntax +1, execution error -100, partial 0-100 (Relaxed Exact Match), full match +1000. SQLCoder-7B EMS 31.49 -> 49.83 — [arXiv HTML](https://arxiv.org/html/2506.06093)
- Reward hacking: CodeGemma learned to return "all the cities where Shevon Jemie Lai won medals" instead of the single answer, collecting 101 points from the partial reward; described as "a risk of purely RL-driven efforts", no fix implemented — [arXiv HTML](https://arxiv.org/html/2506.06093)

**ConstrainedSQL (IBM; Nov 2025; arXiv 2511.09693)** — constrained RL against reward hacking; base model/size and numbers not in the abstract — [arXiv abs](https://arxiv.org/abs/2511.09693v1)

**Agentar-Scale-SQL (Ant Group; Sep 2025, v6 Dec 2025; arXiv 2509.24403)** — orchestrated single-turn pipeline
- Reasoning generator = OmniSQL-32B further trained with GRPO (reward 1.0 correct / 0.1 executable / 0); selector = Qwen2.5-Coder-32B-Instruct, GRPO on 8.5k constructed samples (reward 1/0); BIRD train only. BIRD dev 74.90 full; -4.89 without the RL generator; BIRD test 81.67 — [arXiv HTML](https://arxiv.org/html/2509.24403)

**AGRO-SQL (Dec 2025; arXiv 2512.23366)** — cold start + GRPO, agentic refinement loop (borderline)
- Qwen3-8B-Base; "Diversity-Aware Cold Start" SFT distilled from DeepSeek V3.2 with hybrid-embedding diversity selection and agent-token loss masking (size not stated); GRPO with sparse reward R=1.0 correct / -1.0 invalid format. BIRD dev: cold start only 62.65; GRPO only 63.17; both 72.10. Spider dev 88.39 / 89.26 / 89.13 — [arXiv HTML](https://arxiv.org/html/2512.23366)

**ReToolSQL (JPMorganChase; Aug 2026; arXiv 2608.27796)** — agentic, but has the cleanest SFT / RL / SFT->RL ablation
- Gemma 4 31B Instruct; SFT on rejection-sampled self-traces (teacher-privileged gold-SQL guidance on hard items; only execution-passing traces kept) from 6,601 BIRD train questions; GRPO with DAPO modifications (clip 0.20/0.28, dynamic sampling K=12, decaying KL 0.005->0). Reward: exec 2.0, syntax 0.5, format 0.2, table 0.5, column 0.5, length -0.1. BIRD dev EX / pass@16: base 71.19 / 76.9; SFT only 72.69 / 81.29; RFT from base 73.66 / 77.2; SFT->RFT 74.32 / 81.94; SC@16 74.77 — [arXiv HTML](https://arxiv.org/html/2608.27796v1)

**AutoThinkSQL — Learning When to Reason via SFT and DPO (Jun 2026; arXiv 2607.22622)**
- Qwen3-Coder-30B-A3B-Instruct; SFT on 5,981 self-rollouts from BIRD train (4,625 CoT, 1,356 no-CoT); DPO on 6,064 pairs; no GRPO comparison. BIRD dev greedy 58.23, maj@8 60.27 — [arXiv HTML](https://arxiv.org/html/2607.22622)

**SkyRL-SQL (NovaSky, May/Jun 2025)** — multi-turn (other researcher), cited for its no-SFT, 653-example claim
- Qwen2.5-Coder-7B-Instruct, GRPO in VeRL/SearchR1 loop, reward = format + exact execution match; ~653 training samples; "+7.2% execution accuracy" over base (up to 9.2 on some Spider variants); beats GPT-4o, o4-mini and OmniSQL-7B; multi-turn reached 60% reward 2.8x faster with +16% higher final reward than single-turn. No SFT is mentioned — [Substack write-up](https://machinelearningatscale.substack.com/p/text-to-sql-just-got-a-lot-better); project page [Notion](https://novasky-ai.notion.site/skyrl-sql) (not fetchable)

### Inferences
- Across papers that start from Qwen2.5-Coder-7B-Instruct with GRPO and no SFT, the single-sample BIRD dev plateau is ~60-64 (Reasoning-SQL 64.01; Graph-Reward-SQL EX 64.01; SQL-R1 63.1; CogniSQL 59.97; ReEx 60.8-63.4; CSC-SQL GRPO greedy not stated); starting from OmniSQL-7B (SFT on 2.5M) pushes the same recipe to 66.6-68.9 (SQL-R1, Arctic). The SFT *data scale* (2.5M vs 200K vs 18K) seems to matter more than SFT per se.
- Papers that report "SFT hurt" (SQL-R1 200K cold start 59.2 < RL-only 63.1; CogniSQL QwQ-trace SFT 52 -> 46) used distilled CoT whose style mismatched the base model; papers where SFT helped used either massive in-distribution data (OmniSQL) or execution-filtered self-/teacher traces (ReToolSQL, DeepRetrieval).

### Gaps
- Arctic-Text2SQL-R1 does not report a clean "RL from Qwen2.5-Coder-7B-Instruct vs RL from OmniSQL-7B" pair at the same RL setting; only the 32B batch-vs-online comparison surfaced.
- ReEx-SQL and CSC-SQL do not state explicitly whether any SFT preceded GRPO; the fetches found no SFT stage described.
- SkyRL-SQL per-benchmark numbers could not be retrieved (Notion page not fetchable, GitHub README path 404).
- SLM-SQL BIRD numbers from the HTML fetch (74.53 SFT for 1.5B) are inconsistent with the 67.08 figure quoted in search snippets of the ACL version; needs a PDF check.

## Which papers skip SFT entirely (pure RL from the instruct model), and why

### Takeaway
Reasoning-SQL, CSC-SQL, CogniSQL-R1-Zero, DeepRetrieval ("RL from scratch" arm), RingSQL, SQL-Zero, ReEx-SQL, SQL-R1's 14B config and SkyRL-SQL all run GRPO/PPO straight from a Qwen2.5-Coder-Instruct checkpoint. Their stated reasons: SFT on gold SQL or distilled CoT overfits / generalises worse (Reasoning-SQL, CogniSQL, DeepRetrieval), and SFT on a 200K distilled subset actually lowered the post-RL score (SQL-R1). No paper reports RL-from-instruct failing to train at 3B-7B.

### Cited Findings
- Reasoning-SQL: GRPO directly from Qwen2.5-Coder; SFT used only as baseline; "RL-only training with our proposed rewards consistently achieves higher accuracy and superior generalization compared to supervised fine-tuning (SFT)"; Spider generalisation gap SFT 68.08 vs GRPO 78.72 (7B) — [arXiv abs](https://arxiv.org/abs/2503.23157); [arXiv HTML v2](https://arxiv.org/html/2503.23157v2)
- SQL-R1: RL-only 7B 63.1 vs SFT(SynSQL-200K)->RL 59.2 on BIRD dev; 14B RL-only 67.1 vs OmniSQL-14B->RL 66.6; "SFT cold-start training is not universally essential" — [arXiv HTML v5](https://arxiv.org/html/2504.08600v5)
- CogniSQL-R1-Zero: GRPO "directly on Qwen2.5-Coder-7B without any supervised warm-up"; distilled-trace SFT dropped accuracy ~52.0 -> ~46.0; pure RL "achieved marginally higher peak accuracy" than brief-SFT cold start; 59.97 single-sample — [arXiv HTML](https://arxiv.org/html/2507.06013)
- DeepRetrieval: "RL from scratch achieves better performance than SFT" on all three models (e.g. Coder-3B SFT 39.77 vs RL 49.02 on BIRD) — [arXiv HTML v3](https://arxiv.org/html/2503.00223v3)
- CSC-SQL: GRPO "post-training" of Qwen2.5-Coder-3B/7B-Instruct with R = R_EX + 0.1*R_format; no SFT stage described — [arXiv HTML v2](https://arxiv.org/html/2505.13271v2)
- RingSQL: "No supervised fine-tuning (SFT) step reported"; RLVR on 3B-8B with the SQL-R1 reward — [arXiv HTML](https://arxiv.org/html/2601.05451)
- SQL-Zero: no SFT, no human labels; self-play GRPO raises 3B BIRD dev 38.7 -> 45.3 and 7B 51.1 -> 58.4 — [arXiv HTML](https://arxiv.org/html/2609.04697)
- SkyRL-SQL: ~653 samples, GRPO, no SFT mentioned, beats OmniSQL-7B which was SFT'd on 2.5M — [Substack](https://machinelearningatscale.substack.com/p/text-to-sql-just-got-a-lot-better)
- Arctic-Text2SQL-R1 is the main counter-voice: "Stronger SFT models (e.g., OmniSQL) consistently yield better downstream RL results" — [arXiv HTML v2](https://arxiv.org/html/2505.20315v2)

### Inferences
- "Skip SFT" works in these papers because the base is an *instruction-tuned coder* that already emits valid SQL at 45-59% BIRD dev; none of them start from a raw base model. The one Base-model paper (AGRO-SQL, Qwen3-8B-Base) found GRPO-only 63.17 vs cold-start+GRPO 72.10, i.e. a 9-point gap.

### Gaps
- No single-turn paper trains RL from a *non-instruct base* model at 1.5B-4B; the R1-Zero question for small base models is untested in this literature.

## Which papers use distilled SFT, and what the SFT-vs-RL ablations showed

### Takeaway
Distilled-SFT papers use DeepSeek-R1 (Think2SQL, FINER-SQL), DeepSeek-R1-Distill-Qwen-32B + o1-mini (Reward-SQL v1), DeepSeek-V3.1/V3.2 (Reward-SQL v3, AGRO-SQL), GPT-4o (ExCoT, Graph-Reward-SQL CTE conversion, FINER-SQL), Gemini-1.5-Pro (Reasoning-SQL's STaR-SFT baseline) or the OmniSQL mixture (SQL-R1, SLM-SQL). Ablations are mixed: SFT->RL beat RL-only in DeepRetrieval (3B, +1.5-2.6), AGRO-SQL (+8.9), ReToolSQL (+0.66) and Arctic; RL-only beat SFT->RL in Think2SQL (3B 0.500 vs 0.482; 7B 0.561 vs 0.537) and SQL-R1 (63.1 vs 59.2 with 200K SFT).

### Cited Findings
- Think2SQL (DeepSeek-R1 traces, 1,142 ex.): 3B SFT 0.460, RL-QATCH 0.500, SFT+RL 0.482; 7B SFT 0.494, RL-QATCH 0.561, SFT+RL 0.537 — [arXiv HTML](https://arxiv.org/html/2504.15077)
- SQL-R1 (OmniSQL-style CoT, 200K): SFT->RL 59.2 vs RL-only 63.1 (7B); but 2.5M-SFT (OmniSQL) -> RL 66.6 — [arXiv HTML v5](https://arxiv.org/html/2504.08600v5)
- Reward-SQL v1 (R1-Distill-32B + o1-mini CoCTE, 18,015 ex.): SFT 54.4 -> SFT+GRPO 59.7 -> +PRM@32 68.9; v3 (DeepSeek-V3.1, 51,996 ex.): SFT 63.2 vs GRPO-outcome 62.6 vs GRPO-process+outcome 66.0 greedy — [arXiv HTML v1](https://arxiv.org/html/2505.04671v1); [arXiv HTML](https://arxiv.org/html/2505.04671)
- FINER-SQL (4-teacher 37.6K): 3B SFT ~63.4 -> GRPO 67.73 — [arXiv HTML](https://arxiv.org/html/2605.03465v1)
- AGRO-SQL (DeepSeek V3.2 distillation): cold start only 62.65, GRPO only 63.17, both 72.10 (BIRD dev) — [arXiv HTML](https://arxiv.org/html/2512.23366)
- ExCoT (GPT-4o CoT, 5.6k BIRD): SFT gives +0.8 (70B) and +0.7 (32B) on BIRD; the on-policy DPO stages give +10 — [arXiv HTML](https://arxiv.org/html/2503.19988)
- Reasoning-SQL: Gemini-generated STaR-SFT baseline (7B 61.53) is below GRPO (64.01) — [arXiv HTML v2](https://arxiv.org/html/2503.23157v2)
- CogniSQL: SFT on QwQ-32B traces lowered accuracy (~52 -> ~46) before RL rescued it — [arXiv HTML](https://arxiv.org/html/2507.06013)
- Arctic: RL from OmniSQL checkpoints; 7B 68.9 vs OmniSQL-7B's 63.9 (OmniSQL number from [OmniSQL HTML](https://arxiv.org/html/2503.02240)) — [arXiv HTML v2](https://arxiv.org/html/2505.20315v2)

### Inferences
- The sign of the SFT->RL vs RL-only ablation tracks (a) data scale and (b) distribution match: small distilled sets (1K-200K) from a differently-styled teacher tend to hurt or wash out; the 2.5M in-distribution OmniSQL SFT helps.
- Reward-SQL's v1 -> v3 change (Qwen2.5-Coder-7B + 18K traces -> Qwen3-8B + 52K traces) moved SFT-only greedy from 54.4 to 63.2, so the SFT stage itself is sensitive to teacher quality.

### Gaps
- Think2SQL's SFT+RL arm uses the same 1,142-example SFT model as init; whether a larger SFT set would flip the result is untested.

## Which papers use self-taught / rejection-sampling SFT on the same small model

### Takeaway
STaR-SQL (Llama-3.1-8B, Spider), ReToolSQL (Gemma 4 31B self-traces with gold-SQL hints), AutoThinkSQL (Qwen3-Coder-30B-A3B self-rollouts) and CogniSQL's 36K self-generated corpus are the RFT/STaR-style instances; CogniSQL found self-generated SFT (~57.3) safer than distilled SFT (~46) but still below RL (59.97).

### Cited Findings
- STaR-SQL: Llama-3.1-8B-Instruct, 7,000 Spider train x 8 samples, gold-SQL-hinted rationalisation, execution filtering, ORM verifier; Spider dev 68.6 (SFT) -> 75.0 (STaR) -> 86.6 (ORM@16) — [arXiv HTML](https://arxiv.org/html/2502.13550)
- ReToolSQL: rejection-sampled self-traces (privileged gold-SQL guidance on hard questions), execution-filtered; SFT only 72.69 vs base 71.19; SFT->RFT 74.32 — [arXiv HTML](https://arxiv.org/html/2608.27796v1)
- CogniSQL: 36,356 Qwen-7B-Coder self-generated, execution-validated traces; SFT on them recovered to ~57.3 vs ~46 for distilled-trace SFT — [arXiv HTML](https://arxiv.org/html/2507.06013)
- AutoThinkSQL: 16 self-rollouts per BIRD train item -> 5,981 SFT instances, then 6,064 DPO pairs — [arXiv HTML](https://arxiv.org/html/2607.22622)
- SQL-o1's Progressive SQL Generation data (prefix-truncated failure cases, 21,254 pairs) is a related self-correction-style SFT — [arXiv HTML](https://arxiv.org/html/2502.11741)

### Inferences
- Self-generated SFT avoids the style mismatch that hurt distilled SFT in CogniSQL and SQL-R1, which makes it the natural warm start for a 1.7B-4B model that already produces parsable SQL.

### Gaps
- No paper runs STaR/RFT-style SFT on a <=4B model and then RL; STaR-SQL stops at SFT+ORM and has no BIRD numbers.

## Reward components beyond execution accuracy, and reward hacking

### Takeaway
Useful extras reported with numbers: format tags (nearly universal, weight 0.1-ish), QATCH-style partial cell/tuple credit (Think2SQL: 15-30% relative gain over SFT), schema/n-gram/syntax/LLM-judge (Reasoning-SQL, small per-component gains), PRM/process rewards (Reward-SQL +3.4 greedy over outcome-only), CTE stepwise matching (Graph-Reward-SQL +5.87 BIRD), memory/atomic structural rewards (FINER-SQL +4.44 combined). Arctic-Text2SQL-R1 and Reinforcing-Code-Generation report hacking of partial rewards; Arctic therefore kept 1 / 0.1 / 0.

### Cited Findings
- Arctic: "More fine-grained reward designs induced 'lazy' behaviors, where models pursued local optima for short-term rewards rather than global correctness" — tried execution, syntax, n-gram, schema, format partial rewards and dropped them; kept 1 / 0.1 (executable) / 0 — [arXiv HTML v2](https://arxiv.org/html/2505.20315v2)
- Reinforcing Code Generation: CodeGemma-7B exploited a 0-100 Relaxed-Exact-Match partial reward by returning over-broad result sets, gaining 101 points — [arXiv HTML](https://arxiv.org/html/2506.06093)
- ConstrainedSQL (Nov 2025) frames reward hacking as the motivation for constrained RL with multiple constraint signals — [arXiv abs](https://arxiv.org/abs/2511.09693v1)
- Think2SQL: QATCH partial reward (cell precision, cell recall, tuple cardinality) "crucial"; R = 0.85 task + 0.10 format + 0.05 tag-count — [arXiv HTML](https://arxiv.org/html/2504.15077)
- Reasoning-SQL: weights EX 3, LLM-judge 2, others 1, chosen so no wrong SQL can outscore a correct one — [arXiv HTML](https://arxiv.org/html/2503.23157)
- SQL-R1: graded +-1 / +-2 / +-3 format / execution / result plus length; ablations say balanced weights prevent "exploitation" of simpler patterns — [arXiv HTML](https://arxiv.org/html/2504.08600)
- Reward-SQL v3: GRPO outcome-only 62.6 vs process+outcome 66.0 greedy; PRM@32 70.3 — [arXiv HTML](https://arxiv.org/html/2505.04671)
- Graph-Reward-SQL: execution-free GMNScore reward 47x faster than execution; StepRTM +5.87 on BIRD for 1.3B — [arXiv HTML](https://arxiv.org/html/2505.12380)
- FINER-SQL: dropping memory reward -2.22 EX and syntax errors 6.0% -> ~10%; dropping atomic -3.26; both -4.44 — [arXiv HTML](https://arxiv.org/html/2605.03465v1)
- Arctic also filtered ~3,100 training items whose gold query returns empty results because they yield "spurious or uninformative rewards" — [arXiv HTML v2](https://arxiv.org/html/2505.20315v2)
- SQL-Zero: template-level repetition penalty to prevent structural collapse of the challenger — [arXiv HTML](https://arxiv.org/html/2609.04697)
- CSC-SQL, SLM-SQL, CogniSQL, AGRO-SQL, Agentar-Scale-SQL all use essentially binary execution + small format term and report no hacking — [CSC HTML](https://arxiv.org/html/2505.13271v2); [SLM-SQL HTML](https://arxiv.org/html/2507.22478); [AGRO HTML](https://arxiv.org/html/2512.23366); [Agentar HTML](https://arxiv.org/html/2509.24403)

### Inferences
- The two documented hacks both involve rewards that give partial credit for *result overlap* (n-gram / relaxed match); structure-based partial credit (QATCH cardinality, clause Jaccard, CTE-step match) has not been reported as hacked, but these papers also did not look hard for it.
- Arctic's empty-result filtering is directly relevant to DySQL-style write tasks whose gold affects 0 rows (no-op gold).

### Gaps
- No paper quantifies how often reward hacking occurred (fraction of rollouts); only anecdotes and the Arctic design statement.

## Evidence on 1.5B-4B models: does RL from the instruct model work without SFT?

### Takeaway
RL-from-instruct works at 3B in every paper that tried it (Reasoning-SQL 3B 45.17 -> 58.67; DeepRetrieval Coder-3B 30.77 -> 49.02; CSC-SQL 3B GRPO+SC 60.60; RingSQL Qwen-3B 53.13; SQL-R1-3B 54.6; SQL-Zero 3B 38.7 -> 45.3), and at 1.3B-1.5B in Graph-Reward-SQL (DeepSeek-Coder-1.3B after SFT warm-up) and Think2SQL (Think2SQL-1.5B 0.442 vs base 0.275). But the two papers that did SFT-vs-RL grids at <=3B found the warm start helps: DeepRetrieval SFT->RL > RL-only at 3B (+2.6 / +1.5), Think2SQL says small models "benefit most from reasoning-aware SFT and RL", and SLM-SQL finds removing SFT costs 8.9-21.9 points at 1.5B/0.5B. The strongest small-model results (SLM-SQL 1.5B, FINER-SQL 3B 67.73, CSC-SQL 3B) all include an SFT stage.

### Cited Findings
- Reasoning-SQL 3B: Base 45.17, SFT 55.9, GRPO 58.67 (no SFT before GRPO) — [arXiv HTML v2](https://arxiv.org/html/2503.23157v2)
- DeepRetrieval Qwen2.5-Coder-3B: zero-shot 30.77, SFT 39.77, RL-only 49.02, SFT->RL 50.52 (BIRD); Spider 50.97 / 58.61 / 74.85 / 74.34; "SFT can provide a strong initialization for RL especially when the LLM lacks a certain capability" — [arXiv HTML v3](https://arxiv.org/html/2503.00223v3)
- Think2SQL: 3B RL-only 0.500 > SFT+RL 0.482 > SFT 0.460 > base 0.382; Think2SQL-1.5B 0.442 (base 0.275), 0.5B 0.254 (base 0.089); authors: small LLMs "benefit most from reasoning-aware SFT and RL" and "task-specific reasoning traces are essential" — [arXiv HTML v5](https://arxiv.org/html/2504.15077v5); [arXiv abs](https://arxiv.org/abs/2504.15077)
- SLM-SQL 0.5B/1.5B: SFT then GRPO; ablation: removing SFT -21.93 (0.5B) and -8.89 (1.5B) — [arXiv HTML](https://arxiv.org/html/2507.22478)
- FINER-SQL 0.5B / 1.5B / 3B after SFT+GRPO: 50.85 / 63.17 / 67.73 BIRD dev — [arXiv HTML](https://arxiv.org/html/2605.03465v1)
- CSC-SQL Qwen2.5-Coder-3B (no SFT): GRPO+SC@64 60.60, GRPO+CSC 63.34 vs base SC 56.15 — [arXiv HTML v2](https://arxiv.org/html/2505.13271v2)
- RingSQL Qwen2.5-Coder-3B RLVR without SFT: BIRD dev 53.13 (synthetic data) / 46.74 (BIRD train) — [arXiv HTML](https://arxiv.org/html/2601.05451)
- SQL-R1-3B (RL from instruct, SynSQL-Complex-5K): BIRD dev 54.6, Spider test 78.9 — [arXiv HTML v5](https://arxiv.org/html/2504.08600v5)
- SQL-Zero 3B self-play without labels: BIRD dev 38.7 -> 45.3 — [arXiv HTML](https://arxiv.org/html/2609.04697)
- Graph-Reward-SQL DeepSeek-Coder-1.3B (after SFT warm-up): Spider TS 65.28-68.67, BIRD TS 17.21-21.97 — [arXiv HTML](https://arxiv.org/html/2505.12380)
- Multi-turn cross-reference (other researcher): TRUST-SQL reports that "applying GRPO directly without SFT yields substantially lower performance" and SFT warm-up "instills structured exploration behavior" — search snippet only, [arXiv](https://arxiv.org/pdf/2603.16448)

### Inferences
- For a 1.7B-4B Qwen-class instruct model on *single-turn* SQL, RL-only is viable and gives +10-18 points on BIRD dev from the instruct baseline (Reasoning-SQL, DeepRetrieval), but an execution-filtered SFT warm start (self-generated or in-distribution) adds a further ~1.5-3 points at 3B and much more at <=1.5B (SLM-SQL). The disagreement (Think2SQL) arises when the SFT set is tiny (1,142) and distilled from a very different model (DeepSeek-R1).
- None of these papers involve tool-use formats, multi-step agent loops or write statements; the format-learning burden in an agentic setting is larger, which is where the multi-turn literature (TRUST-SQL, AGRO-SQL's agentic variant) reports SFT being necessary.

### Gaps
- No single-turn paper reports a 1.5B-4B model trained with RL from a *base* (non-instruct) checkpoint; no paper reports training collapse / format failure numbers for 1.5B RL-only.
- Qwen3-1.7B / Qwen3-4B specifically: no single-turn text-to-SQL RL paper found (SLM-SQL uses Qwen3-0.6B only; Reward-SQL v3 and AGRO-SQL use Qwen3-8B).
